# Demo data and artwork

All catalog products, specifications, prices, stock quantities and brand names in this directory are fictional portfolio fixtures, not customer data or commercial offers.

- `catalog.json`: canonical six-product Biurko / Lab catalog, in three categories. Descriptions identify the demonstration context.
- `products.csv`: equivalent synchronizer input, generated by `scripts/build-demo-csv.py` using the local media manifest.
- `media.local.json`: non-secret attachment IDs from the verified local database. They are examples, not portable identifiers. Regenerate through demo setup for a new database.
- `products.example.csv`: two minimal fictional draft products retained to demonstrate the required CSV fields; not part of the six-product storefront.

Required fields: `sku,name,regular_price,stock_quantity,status`. Optional fields: `description,short_description,categories,image_id,image_url,image_alt`. CSV uses UTF-8, commas and decimal points. Existing category slugs are separated by `|`. JSON `asset` names resolve through the media manifest. Missing optional fields are unmanaged; present empty values have different semantics.

Artwork in `../assets/` and the theme was created for this project with `scripts/draw-assets.py`; no scraped product photographs or client images are used. Rendering is optional (Pillow required); checked-in PNGs are sufficient for setup. There is no repository-wide open-source license selected yet; public visibility alone would not grant general reuse rights.

Evidence in `../docs/` contains local product/order IDs and fictional order totals, not customer contact details. Logs, credentials, database dumps and transient AI proposals must remain untracked.
